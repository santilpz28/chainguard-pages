Mirai's Eyes — RSA partial disclosure + JWT forgery

A Flask web app authenticates users with a custom RSA-signed JWT. The private key ships in the source, but 620 base64 characters of it are censored. Inside the visible suffix, three CRT parameters survive — and that's enough to factor a 2048-bit modulus in seconds, recover the private exponent, and forge an admin token that unlocks a hidden camera whose frames contain the flag.

Bottom line

The challenge gives you a Flask app with private.pem censored in the middle. The visible suffix contains q (partial), dp, dq, qInv. The Bleichenbacher attack on dp reduces the problem to brute-forcing k ∈ [1, 10⁵] in the equation e · dp − 1 = k · (p − 1). Once p is found, q = n/p, d = e⁻¹ mod φ(n), and you can sign your own JWT with role: admin, groups: [Oficina, Restaurante]. The dashboard then exposes the hidden flag-*.mp4 camera. Every frame of that video contains the flag rendered as giant white text on a black background. Total solve time: ~3 hours from cold start.

1. What you get

The challenge archive is the full Flask source. Layout:

Mirais_Eyes/
├── app/
│   ├── app.py
│   ├── utils.py                ← JWT logic, "MIRAI_ALG" custom
│   ├── data/
│   │   ├── public.pem
│   │   └── private.pem         ← 620 chars b64 censored
│   ├── static/cameras/
│   │   ├── 1.mp4 … 5.mp4       ← recycled 2011-2013 CCTV footage
│   │   └── REDACTED.mp4        ← 0-byte placeholder
│   └── templates/{login,register,dashboard,index}.html
└── Dockerfile

The five normal cameras ship in the archive; the flag camera (flag-*.mp4) only exists on the live server. The source is gunicorn + Flask, the JWT is custom-named MIRAI_ALG but the actual signature is bog-standard PKCS#1 v1.5 + SHA-256.

2. Recon

Fuzzing 800+ paths returned only four interesting endpoints: /, /login, /register, /dashboard, and /static/*. SQLi on /register was a dead end (parameterised). Path traversal on /static was blocked (Flask + gunicorn). No robots.txt, no debug pages, no .well-known anything.

The dashboard accepts a cookie called token which contains the JWT. If the signature is invalid, you get a 302 to /login. If the signature is valid but the user lacks permission for any camera group, you get a 200 with an empty camera list. The trick is that the sixth camera — id=flag — is filtered client-side: it's only added to the JSON list when the JWT payload contains role: admin.

One small Easter egg: the landing page is mostly fancy-font Mirai-themed marketing text, but the title block contains a reversed string that decodes to trabajo (Spanish for "work"). Don't skim past decorative text in CTFs.

3. The censored key

private.pem is a PKCS#8 RSAPrivateKey with 620 base64 characters redacted with REDACTEDREDACTED… in the middle. Structure:

-----BEGIN PRIVATE KEY-----
MII…
<302 chars b64 — header + first INTs>REDACTED…REDACTED
<302 chars b64 — trailing INTs>
-----END PRIVATE KEY-----

The standard DER field order of an RSAPrivateKey is:

SEQUENCE
  INTEGER  version
  INTEGER  modulus         (n)
  INTEGER  publicExponent  (e)
  INTEGER  privateExponent (d)
  INTEGER  prime1          (p)
  INTEGER  prime2          (q)
  INTEGER  exponent1       (dp = d mod p−1)
  INTEGER  exponent2       (dq = d mod q−1)
  INTEGER  coefficient     (qInv = q⁻¹ mod p)

620 chars b64 ≈ 465 bytes of DER. That's wide enough to swallow d plus most of p. But the trailing INTEGERs — q (partially), dp, dq, qInv — are intact in the visible suffix. And that's enough to break the key.

4. Bleichenbacher attack on dp

The math is brutal:

e · dp ≡ 1   (mod p − 1)
⟹  e · dp − 1 = k · (p − 1)   for some integer k > 0

Since 0 < dp < p − 1, we have 0 < k < e. For e = 65537 that's ~65k candidates. For each k, compute the candidate p and test n mod p == 0:

for k in range(1, 100_001):
    num = e * dp - 1
    if num % k != 0: continue
    p_cand = num // k + 1
    if p_cand < 2 or p_cand >= n: continue
    if n % p_cand == 0:
        q = n // p_cand
        return p_cand, q

The naive bound assumes k < e, but in this key the working k turned out to be 50084 — slightly above 65537/2 because the author engineered a key where e · dp − 1 overshoots by more than one multiple of p − 1. Brute force up to 10⁵ still completes in <1 second on a laptop. The solver prints p and q in 256-decimal form for archival.

Once p and q are known:

phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)

5. Forging the admin JWT

utils.py builds JWTs as header_b64 + "." + payload_b64 + "." + sig_b64 with URL-safe base64 (no padding) and signs with PKCS#1 v1.5 + SHA-256. The custom header field "alg": "MIRAI_ALG" is just a string rename — there's nothing exotic. With d in hand, signing your own token is trivial:

from Crypto.Signature import pkcs1_15
from Crypto.Hash import SHA256
import base64, json

key = RSA.construct((n, e, d, p, q))
header_b64  = base64.urlsafe_b64encode(
    b'{"alg":"MIRAI_ALG"}').rstrip(b"=")
payload_b64 = base64.urlsafe_b64encode(
    json.dumps({"groups":["Oficina","Restaurante"],
                "role":"admin","user":"admin"},
               separators=(",",":")).encode()
).rstrip(b"=")

signing_input = header_b64 + b"." + payload_b64
sig = pkcs1_15.new(key).sign(SHA256.new(signing_input))
sig_b64 = base64.urlsafe_b64encode(sig).rstrip(b"=")
token = (signing_input + b"." + sig_b64).decode()

Send it as the token cookie:

curl http://<host>:31856/dashboard -H "Cookie: token=<forged_jwt>"

The dashboard now lists six cameras, including the hidden flag-2d2edcb99ecc4b6c496e85bc42d4dc2f.mp4.

6. Pulling the flag

Direct download — the /static endpoint is not auth-gated, only filtered client-side from the dashboard JSON, so anyone with the camera URL can curl it:

curl -o flag.mp4 \
  http://<host>:31856/static/cameras/flag-2d2edcb99ecc4b6c496e85bc42d4dc2f.mp4 \
  -H "Cookie: token=<forged_jwt>"

The file is ~340 KB, ~15 seconds, 25 fps, 1620×1080. Open any frame: the flag is overlay text in white on black, ~120 px tall, perfectly centred. The text is baked into every frame — there's no flicker, no per-frame change. Reading one frame is enough; reading 375 just confirms consistency.

7. What this challenge teaches

  • Partial private key disclosure is fatal. Even when d is destroyed, the CRT parameters (dp, dq, qInv) by themselves collapse RSA-2048 in seconds. Defence: never publish anything from a private key, including the CRT fields.
  • Custom JWT algorithm names are not security. "MIRAI_ALG" looked exotic but was bog-standard PKCS#1 v1.5 + SHA-256 with a header field rename. Always verify the algorithm against actual signer behaviour, not the JWT spec.
  • Permission checks belong on the server, not the URL. /static/cameras/flag-*.mp4 was not auth-gated — only filtered client-side from the dashboard JSON. Once you have the URL, anyone can curl it. Classic IDOR.
  • Marketing copy can hide breadcrumbs. The reversed trabajo on the landing page is the author's signature: "look harder at the work, not the marketing." Don't skim past decorative text in CTFs.
  • Recycled footage is a fun red herring. The five normal cameras are all 2011–2013 Spanish CCTV footage tagged MANC260987 — unrelated noise. Easy to waste hours on them if you don't read the source carefully first.
